# adulting

Plain-text vault tools. `README.md` holds the design, `MANUAL.md` the
generated command reference, and `dev/ci` the gate.

## The real vault is private

The owner's vault (`~/vault`, or wherever `ADULTING_HOME` points) holds
real clients, people, money and family matters. You may read it to
reproduce a bug or check a migration. Nothing from it goes into this repo.

**Never copy anything from the real vault into a tracked file, a commit
message or a PR description.** That covers:

- thread names (`Projects/<client>`, `Processes/<…>`, `Topics/<…>`)
- people's names, and initials or nicknames that stand for them
- client legal names, addresses, VAT numbers, emails and phone numbers
- note stems, topics, log lines, task text, hours descriptions
- amounts, rates, currencies and bank details tied to a real client
- school, employer, bank or place names that identify someone

It applies everywhere: README, MANUAL, CHANGELOG, `stories/`, schemas,
docstrings, help strings, `dev/tools/`, `agent/skills/` and `tests/`.

Aggregate facts with nothing identifying in them are fine: "365 files
moved", "lint reports 18 violations before and after", "0.31s against
0.28s".

### Use the invented names

Use these in docs, stories, skills, help strings and docstrings, so
examples agree with each other:

| Kind | Names |
|---|---|
| Owner | `Sam Rivera` (in the agent skills: "the owner") |
| People | `Jordan Blake`, `Leah Rivera`, `Mia Rivera`, `Ivan Petrov`, `Priya`, `Omar Haddad`, `Dana Kim` |
| Billable threads | `Projects/Northwind`, `Projects/Contoso Partners`, `Projects/Fabrikam DORA`, `Projects/Halcyon` |
| Other threads | `Processes/Rivera Family Trust`, `Processes/Fitness`, `Processes/Chores`, `Processes/Money`, `Topics/Family` |

The tests have their own set (`SQR`, `Remy Dorn`, `Bram Halvorsen`,
`SARO Partners`, `AVO DORA`, `Workouts`), each the same length and initial
as the name it replaced, because the CLI's tables pad to name length and
some tests pin sort order. Reuse them in new tests.

Need a name that isn't listed? Make one up, and check it isn't a thread or
person in the real vault:

```sh
ls ~/vault/threads/*/ ~/vault/people/ | grep -i '<name>'
```

### When a bug comes from the real vault

Reproduce it there if you need to, then write the test, the story and the
CHANGELOG entry with invented names and invented content that shows the
same shape. "A note linking `[[people/Omar haddad]]` where the file is
`Omar Haddad.md`" makes the point; the real note doesn't need to.

### The agent skills are different

`agent/skills/` drives the agent *against* the real vault, so at run time
it uses real names. That's correct. Only the examples written into the
skill files must be invented.

## Generated files

`MANUAL.md` and `dev/tools/*.json` are generated by `dev/ci generate` from
the CLI's `--help-json`, docstrings, help strings, the schemas and some
README sections. Fix the source, never the output. Their prompts
(`dev/manual-prompt.md`, `dev/tools-prompt.md`) carry the same naming rule.
